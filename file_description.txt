# File Descriptions and Code Flow

## Project Overview
This is a Social and Flirting Confidence Simulator built with FastAPI, using Hume AI for emotion analysis to provide real-time feedback on social interaction skills through Flirting Response Score (FRS) computation.

## File Structure and Descriptions

### Root Level Files
- `main.py`: FastAPI application entry point, sets up CORS, mounts static files, includes routers, and defines feedback endpoint
- `requirements.txt`: Python dependencies with pinned versions
- `README.md`: Project documentation and setup instructions
- `TODO.md`: Development task tracking
- `sessions.db`: SQLite database for session storage
- `.env`: Environment variables (not in repo)
- `.gitignore`: Git ignore patterns

### API Layer (`api/`)
- `api/routes/frs.py`: FRS (Flirting Response Score) endpoints for WebSocket streaming, calibration, baseline setup, and video upload
- `api/routes/session.py`: Session management endpoints for creating, ending sessions, and retrieving scenarios/modes

### Core Logic (`core/`)
- `core/__init__.py`: Core module initialization
- `core/constant.py`: Application constants and configuration
- `core/scoring.py`: FRS computation logic using emotion data and baselines
- `core/session_store.py`: SQLite-based session and summary storage
- `core/data_contract/__init__.py`: Data contract exports
- `core/data_contract/_static_enums.py`: Enum definitions (Mode, DocumentationSections)

### Models (`models/`)
- `models/models.py`: Pydantic models for API requests/responses (FRSResult, SessionCreate, etc.)

### Hume AI Integration (`hume_ai/`)
- `hume_ai/hume_ai_client.py`: Hume AI WebSocket client for real-time emotion streaming

### Static Files (`static/`)
- `static/index.html`: Frontend interface

## Code Flow

### Application Startup
1. `main.py` initializes FastAPI app with CORS middleware
2. Mounts static files directory for frontend serving
3. Includes FRS and session routers with prefixes
4. Sets up custom Swagger UI endpoint

### Session Creation Flow
1. User calls `POST /session/start` with user_id, mode, scenario
2. `session.py` validates mode/scenario against predefined scenarios
3. Creates session in `session_store.py` (SQLite database)
4. Returns session_id for subsequent operations

### FRS Calibration Flow
1. User calls `POST /api/calibration/start` with session_id
2. `frs.py` initializes calibration steps (reading lines, expressions, gestures)
3. User completes calibration steps via WebSocket `/api/ws/{session_id}`
4. `hume_ai_client.py` streams emotions from Hume AI
5. `frs.py` accumulates emotion data and computes baseline
6. Baseline stored in memory (production: use DB)

### Real-time FRS Streaming Flow
1. User establishes WebSocket connection to `/api/ws/{session_id}`
2. `frs.py` connects to Hume AI via `hume_ai_client.py`
3. Audio/video stream processed by Hume AI for emotion detection
4. Emotions converted to FRS scores using `scoring.py` with baseline adjustment
5. FRS results sent back via WebSocket and accumulated in memory per session

### Session End Flow
1. User calls `POST /session/end/{session_id}`
2. `session.py` retrieves accumulated FRS scores from memory
3. Computes final aggregated FRS (averages, medals, stars)
4. Generates feedback based on performance thresholds
5. Stores session summary in `session_store.py` database
6. Returns final results and feedback

### Feedback Retrieval Flow
1. User calls `GET /feedback/{session_id}`
2. `main.py` retrieves session summary from `session_store.py`
3. Extracts FRS results and generates feedback display data
4. Returns formatted response for frontend (scores, medals, stars, feedback)

### Video Upload Flow (Bonus Feature)
1. User uploads video via `POST /api/upload_video`
2. `frs.py` saves file and simulates emotion aggregation
3. Computes FRS using `scoring.py`
4. Returns processed results

## Data Flow Summary
- **Input**: Audio/video streams, calibration data, session parameters
- **Processing**: Hume AI emotion analysis → FRS computation → aggregation → storage
- **Output**: Real-time FRS feedback, session summaries, performance metrics
- **Storage**: SQLite for sessions/summaries, in-memory for active streaming data

## Key Components Interaction
- **FastAPI**: HTTP/WebSocket routing and request handling
- **Hume AI**: Real-time emotion detection from media streams
- **Pydantic**: Data validation and serialization
- **SQLite**: Persistent session data storage
- **WebSockets**: Real-time bidirectional communication for streaming FRS
